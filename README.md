# Twelve Shogi Lab

십이장기(どうぶつしょうぎ)를 기준점으로 삼아 HP, 장비, 융합 같은 로그라이크 규칙을 빠르게 만들고 비교하고 폐기하는 웹 실험실입니다. 목표는 첫 아이디어를 지키는 것이 아니라, **재미없으면 안전하게 버릴 수 있는 구조**를 만드는 것입니다.

## 저장소 운영과 다음 세션

이제 모든 변경은 **작업 브랜치 → PR → 독립 리뷰 → 사용자 승인 후 병합**을 거칩니다. `main` 직접 푸시는 금지합니다. 문서상의 규칙과 GitHub 보호 설정은 별개이며, 이번 운영 규칙 PR에서 서버 보호를 설정하지는 않습니다.

## 현재 플레이 가능: Experiment 00

- 3 × 4 원형 보드와 기본 말 이동
- 포획한 말을 내 편으로 다시 놓는 손패
- 병아리 승격과 포획 시 강등
- 사자 포획 및 안전한 트라이 승리
- 사자가 공격받는 칸으로 이동하지 못하는 합법 수 판정
- 동일 국면 3회 반복 무승부
- 모바일에서도 동작하는 CSS 기반 인터페이스
- 한국어·일본어·영어 인게임 UI, 도중 언어 전환 및 언어 선택 저장

말을 선택하면 합법적인 목적지가 표시됩니다. 잡은 말은 판 위·아래의 손패에서 선택해 빈 칸에 놓을 수 있습니다.

현재는 **한 화면에서 양쪽을 직접 조작하는 로컬 2인 대국**입니다. AI 상대, 온라인 대전, 대국 저장, 로그라이크 런, HP·장비·융합은 아직 구현하지 않았습니다. 새로고침하면 대국이 초기화됩니다. 개발 계획은 문서에서 관리하며 인게임에는 현재 플레이에 필요한 정보만 표시합니다.

## 언어 대응

화면 상단에서 `한국어 / 日本語 / English`를 고를 수 있습니다. 첫 방문은 브라우저 선호 언어 중 지원하는 언어를 사용하고, 해당 언어가 없으면 영어로 표시합니다. 직접 고른 언어는 다음 방문에도 우선 적용됩니다. 브라우저가 저장소 접근을 막아도 해당 탭에서 언어를 바꿀 수 있습니다.

언어 전환은 대국 상태, 선택 중인 말, 손패와 턴을 초기화하지 않습니다. 말 이름, 도움말, 행동·승패 메시지, 스크린리더 레이블 및 문서 언어까지 전환합니다. 저장되는 것은 언어 설정뿐입니다.

번역은 `src/i18n/{ko,ja,en}.ts`에서 관리합니다. 공통 `Messages` 타입이 누락된 문구를 빌드 시 검출합니다. 규칙 엔진은 문장을 만들지 않고 `GameEvent`를 반환하며, UI가 현재 언어로 문장을 구성합니다. 개발 문서의 언어는 한국어 중심으로 유지합니다.

기준판의 구현 선택: 자살수는 입력 단계에서 막으며, 합법 수가 없으면 그쪽의 패배로 종료합니다. 원형의 모든 운영 규정을 그대로 복제한 판은 아니며 이 선택은 향후 비교 실험 시 유지하거나 명시적으로 변경합니다.

폰에서는 남쪽 병아리 → 바로 위 북쪽 병아리를 눌러 포획과 손패 추가를 확인하고, 북쪽 말을 이동시킨 뒤 남쪽 손패의 병아리 → 표시된 빈 칸을 눌러 재투입을 확인하세요.

## 로컬 실행

Node.js 22.12 이상을 권장합니다(CI는 Node 22 사용).

```bash
npm install
npm run dev
```

테스트와 프로덕션 빌드:

```bash
npm test
npm run build
```

## 실험 대기열

후보 ID는 개발 순서가 아닙니다. 실제 우선순위와 각 단계의 수용 조건은 [로드맵](docs/roadmap.md), 실험 질문과 폐기 원칙은 [실험 헌장](docs/experiment-charter.md)에서 관리합니다.

## 구조

```text
src/core/          상태와 ruleset 계약
src/rules/         결정론적 게임 규칙
src/experiments/   실험 목록과 메타데이터
src/i18n/          한·일·영 사전, 언어 선택, 대국 메시지 번역
src/ui/            브라우저 인터페이스
tests/             규칙 회귀 테스트
docs/              질문, 관찰, 폐기 기록
.agents/skills/    이 저장소의 변경·독립 리뷰 절차
.github/           PR 템플릿, PR 검증, main 배포
```

## GitHub Pages

`main` 브랜치에 변경이 들어오면 테스트와 빌드를 거쳐 GitHub Pages에 배포하는 워크플로가 포함되어 있습니다. 저장소의 **Settings → Pages → Build and deployment → Source**를 `GitHub Actions`로 한 번 지정하면 다음 주소에서 열 수 있습니다.

<https://hibikukane.github.io/twelve-shogi-lab/>

## 생성 이미지 원칙

최종 이미지가 없어도 모든 핵심 규칙을 시험할 수 있어야 합니다. 생성 이미지를 추가할 때는 `public/assets/<experiment-id>/` 아래에 두고, 사용 모델·출처·라이선스 가정을 같은 폴더에 기록합니다.
