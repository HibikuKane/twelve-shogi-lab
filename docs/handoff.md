## 배포와 실제 플레이의 증거

- 사용자는 이전 기본판을 폰에서 한 판 플레이했다고 보고했다.
- 최신 다국어 버전은 커밋 반영까지 확인했지만 Pages 배포 성공 및 실제 브라우저 조작 결과를 확인하지 못했다. 기본판의 실기기 확인을 최신 다국어 버전 검증으로 대체하지 않는다.
- 게임 주소: <https://hibikukane.github.io/twelve-shogi-lab/>.
- 배포/브라우저 확인 단계의 복합 도구 호출이 장시간 반환되지 않아 사용자가 중단한 일이 두 번 있었다. 정확히 어느 내부 호출이 막혔는지는 확정하지 못했다. 기존 타임아웃 설정도 그 외부 대기를 끊지 못했다.
- 다음 세션은 브라우저 확인을 필수 선행 조건으로 붙여 무기한 대기하지 않는다. 확인 가능할 때 한 단계씩 짧게 보고하고, 실패 시 미확인 항목으로 남긴다.

## 이번 운영 규칙 변경의 지위

- 작업 브랜치: `docs/repository-governance`, 기준 커밋은 위 `9621c99…`.
- 이 문서와 운영 규칙은 해당 브랜치의 PR 제안이다. main에 직접 넣거나 병합하지 않았다. PR 번호/최신 head/리뷰 상태는 GitHub에서 이 브랜치를 기준으로 확인한다.
- 변경 범위: 운영 문서, 저장소 스킬 2개, PR 템플릿, PR 검증 CI, Pages의 main 전용 실행 조건. 게임 코드 변경은 없다.
- 이번 PR의 독립 리뷰와 최신 검증은 PR 본문 및 연결한 검토 보고서를 우선한다. 이 스냅샷의 과거 테스트 수를 현재 PR 성공으로 해석하지 않는다.
- GitHub 보호 규칙은 이번 변경으로 설정하지 않았다. 별도 GitHub 리뷰어 계정도 미지정이다. AI 독립 리뷰 보고서는 공식 계정 Approve와 다르다.

## 다음 세션의 첫 작업

먼저 이 운영 규칙 PR을 사용자와 검토한다. 승인 없이 병합하지 않는다. main 직접 푸시 금지라는 사용자 지시는 이 문서의 병합 전부터 유효하다.

운영 규칙 정리 이후 사용자가 다음 개발을 요청하면 [로드맵의 기본 AI 상대](roadmap.md#다음-기능-후보-기본-ai-상대)를 한 PR의 목적으로 잡는다. AI를 만들면서 기물 수·체크 규칙·런 시스템까지 함께 변경하지 않는다.

## 이어갈 때 잊지 않을 기획

- 초반 소수 기물 시작은 플레이어만 약하게 만드는 구상이 아니다. 극초반 적은 플레이어보다 기물 수가 적어야 한다.
- 개발 계획과 실험 질문은 문서에 둔다. 플레이어는 완결된 현재 게임 흐름을 보아야 한다.
- 융합/진화는 핵심 관심사지만 방식은 미정이다. 후보 ID를 개발 순서나 확정 기획으로 해석하지 않는다.
- 런 보유 기물 / 출전 기물 / 전투 포획 손패를 분리하고, 포획한 말의 영구 편입 여부를 임의로 확정하지 않는다.
