# 실험 헌장

이 저장소는 하나의 완성작을 곧장 키우는 곳이 아니다. 십이장기를 공통 기준점으로 삼아 로그라이크 규칙을 값싸게 만들고, 비교하고, 버리는 실험실이다.

## 지금 묻는 질문

- 원형 십이장기의 긴장은 어디에서 생기는가?
- 사자 포획을 HP 피해로 바꾸면 수읽기가 풍부해지는가, 흐려지는가?
- 장비가 능력치가 아니라 이동·포획 규칙을 바꿀 때 선택이 생기는가?
- `몸체 A + 능력 B` 방식의 비대칭 융합은 결과를 예측할 수 있으면서도 놀라운가?
- 강화·장비·융합된 말을 상대가 잡았을 때 무엇이 넘어가야 공정한가?

## 운용 원칙

1. 한 실험에서는 큰 규칙 하나만 바꾼다.
2. 구현 전에 그 실험이 답할 질문을 한 문장으로 쓴다.
3. 규칙 계산은 결정론적으로 유지하고 화면 코드와 분리한다.
4. 새 효과는 화려함보다 판독 가능성을 먼저 검증한다.
5. 폐기한 실험도 이유와 관찰 결과를 남긴다.
6. 첫 검증은 전용 이미지 없이도 가능해야 한다.

## 초기 대기열

아래 ID는 실험 후보의 식별자이며 실행 순서를 확정하지 않는다. 미구현 실험을 선택 가능한 화면처럼 인게임에 노출하지 않는다.

| ID | 실험 | 변경하는 것 | 변경하지 않는 것 |
|---|---|---|---|
| 00 | 원형 | 없음 | 십이장기 기본 규칙 |
| 01 | HP 전투 | 승패와 피해 | 말의 기본 이동 |
| 02 | 장비 변이 | 말 하나의 작동 방식 | 판 크기와 턴 구조 |
| 03 | 비대칭 융합 | 몸체·능력 조합 | 한 칸 한 말 원칙 |

## 아직 결정하지 않은 것

- HP의 정확한 형태와 회복 규칙
- 융합된 말이 잡혔을 때의 소유권과 분해 여부
- 한 런의 길이, 전투 수, 영구 성장
- 최종 아트 스타일과 이미지 생성 파이프라인
- 수익화 방식

결정하지 않은 것은 결함이 아니라 실험 대상이다.

## 플레이 피드백 이후 개발 순서 (2026-09-06)

1. **인게임 UI 정리 + 한·일·영 대응:** 개발 소개와 실험 질문은 문서에 두고, 게임 화면은 현재 대국의 조작·판독·승패에 집중한다. 한 기기에서 양쪽을 조작하는 현재 모드는 명확히 표시한다. 언어 전환은 대국 상태에 영향을 주지 않는다.
2. **AI 상대:** 초기 배치를 가정하지 않고 현재 상태와 ruleset의 합법 수로 판단하는 상대를 만든다. 혼자서 대국을 끝까지 진행할 수 있는 것이 첫 기준이다.
3. **스테이지와 기물 보상:** 플레이어는 소수의 기물로 시작한다. 극초반 적은 플레이어보다 기물 수가 적어야 하며, 항상 4기물을 가진 적과 싸우는 출발은 피한다. 수적 우위만으로 쉬움이 보장되지는 않으므로 배치·기물 종류·AI도 함께 조절한다. 정확한 수와 배치는 미정이다.
4. **체크 중 다른 수 허용 비교:** 현재 안전 수만 허용하는 기준판을 보존하고, 사자가 노출되는 수를 허용해 실제 포획으로 끝내는 변형은 별도로 검증한다.

### 스테이지 설계 시 분리할 상태

- 런 보유 기물: 전투 사이에도 유지하는 전력.
- 출전 기물: 이번 전투의 시작 시점에 배치할 전력.
- 전투 손패: 해당 대국에서 잡아 재투입할 수 있는 말.

클리어 보상으로 기물을 고르고 이후 출전 가능 수를 확장하는 방식을 후보로 둔다. 사자와 병아리 셋 같은 편성도 선택 결과의 검증 사례다. 포획한 기물의 런 영구 편입, 패배·손실 처리, 출전 수 증가 시점은 아직 미정이다. 런 상태는 현재의 `GameState`에 섞지 않는다.

### 이번 반영 범위

UI 정리와 한·일·영 대응만 구현했다. AI, 스테이지, 기물 수 변화, 체크 규칙 변경은 구현하지 않았으며 기본 대국은 기존 4대4 배치를 유지한다.
