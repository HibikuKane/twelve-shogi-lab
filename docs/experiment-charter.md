# 실험 헌장

이 저장소는 하나의 완성작을 곧장 키우는 곳이 아니다. 십이장기를 공통 기준점으로 삼아 로그라이크 규칙을 값싸게 만들고, 비교하고, 버리는 실험실이다.

## 지금 묻는 질문

- 원형 십이장기의 긴장은 어디에서 생기는가?
- 사자 포획을 HP 피해로 바꾸면 수읽기가 풍부해지는가, 흐려지는가?
- 장비가 능력치가 아니라 이동·포획 규칙을 바꿀 때 선택이 생기는가?
- `몸체 A + 능력 B` 방식의 비대칭 융합은 결과를 예측할 수 있으면서도 놀라운가?
- 강화·장비·융합된 말을 상대가 잡았을 때 무엇이 넘어가야 공정한가?

## 운용 원칙

1. 한 실험에서는 큰 규칙 하나만 바꾼다.
2. 구현 전에 그 실험이 답할 질문을 한 문장으로 쓴다.
3. 규칙 계산은 결정론적으로 유지하고 화면 코드와 분리한다.
4. 새 효과는 화려함보다 판독 가능성을 먼저 검증한다.
5. 폐기한 실험도 이유와 관찰 결과를 남긴다.
6. 첫 검증은 전용 이미지 없이도 가능해야 한다.

## 초기 대기열

아래 ID는 실험 후보의 식별자이며 실행 순서를 확정하지 않는다. 미구현 실험을 선택 가능한 화면처럼 인게임에 노출하지 않는다.

| ID | 실험 | 변경하는 것 | 변경하지 않는 것 |
|---|---|---|---|
| 00 | 원형 | 없음 | 십이장기 기본 규칙 |
| 01 | HP 전투 | 승패와 피해 | 말의 기본 이동 |
| 02 | 장비 변이 | 말 하나의 작동 방식 | 판 크기와 턴 구조 |
| 03 | 비대칭 융합 | 몸체·능력 조합 | 한 칸 한 말 원칙 |

## 아직 결정하지 않은 것

- HP의 정확한 형태와 회복 규칙
- 융합된 말이 잡혔을 때의 소유권과 분해 여부
- 한 런의 길이, 전투 수, 영구 성장
- 최종 아트 스타일과 이미지 생성 파이프라인
- 수익화 방식

결정하지 않은 것은 결함이 아니라 실험 대상이다.

## 実験記録 / 실험 기록

구현 전에는 질문과 비교 기준, 바꿀 규칙을 적는다. 플레이 후에는 관찰과 유지·수정·폐기 판단을 적는다. 실패한 실험의 문서는 남기고, 코드가 제거되었다면 마지막 관련 PR을 연결한다.

개발 우선순위와 스테이지 설계 경계는 [로드맵](roadmap.md), 목표·제약·미정 기획은 [프로젝트 목표](project-goals.md), 실제 반영/검증 상태는 [인계](handoff.md)에서 관리한다.
